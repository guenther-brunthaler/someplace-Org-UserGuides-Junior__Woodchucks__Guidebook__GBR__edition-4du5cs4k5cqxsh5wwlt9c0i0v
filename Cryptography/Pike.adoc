Pike
====
2026.314

The Pike stream cipher was invented by Ross Anderson to be a "leaner and meaner" version of FISH ("Fibonacci Shrinking Generator") after he broke FISH in 1994. Its name is supposed to be a humorous allusion to the pike fish.

It is about 10% faster than FISH, yet believed to be much stronger. It potentially has a huge key length, and no attacks have been published as of 2004.

Pike consists of three lagged Fibonacci generators with relations

....
a[i] = mod(a[i - 55] + a[i - 24], 2 ^ 32)
b[i] = mod(b[i - 57] + b[i - 7], 2 ^ 32)
c[i] = mod(c[i - 58] + c[i - 19], 2 ^ 32)
....

For every generator value there exists an associated carry bit. It tells whether the addition used for producing the generator value resulted in an overflow which had to be reduced to a smaller value by the modulo operation.

When two values are added and then being reduced modulo some modulus, the value of the carry bit for this addition is 1 if the sum after modulo reduction is smaller than any of its addends, and 0 otherwise. (This will then actually apply to both addends, so it does not matter which addend is compared to the modulo-reduced sum and there is no need to also compare the other one.)

The values of the carry bits associated with the current values of all generators are compared in order to form a control decision for each generator.

If the carry bits of all three generators are the same, then the control decision is true for all generators. Otherwise, the control decision will be true only for those two generators which have identical carry bits, and false for the remaining generator. (This can be equivalently stated as: The control decision for a generator is true if at least one of the other two generators has the same carry bit value as the generator in question. Otherwise it is false.)

Pike works in cycles.

Every cycle consists of "stepping" all three or just two of the generators. If the control decision for a generator is true then it is stepped. Otherwise it keeps its value and associated carry bit from the last cycle. Then the current values of all three generators are combined to produce the next output value, and the next cycle begins.

"Stepping" a generator means to increment its function argument, an index value ("i" in the above generator definitions). Initially, all generator functions must start with the same index value. The actual value does matter because any starting value for all three generators will produce the same results.

When the control decision for a generator in a cycle instructs the generator to be stepped, the index value of the generator will be incremented. Otherwise it will stay the same.

As explained before, the control decisions for the generators are derived from the carry bits of the additions.

However, those control decisions have to be delayed for 8 cycles.

Which means the control decisions of the current cycle are defined by the states of the carry bits as they were 8 cycles ago.

In the initial 8 cycles, there exist no control decisions from 8 cycles ago. Therefore, all generators must be stepped unconditionally.

However, those initial cycles will not produce any output. Their purpose is just to calculate the carry bits (and thus the control decisions) for the cycles which follow.

For the 9th and following cycles, output is produced as follows: The sum of all current values of all three generators is calculated, and the 16 low-order bits of this sum are output as the next 16-bit result word.

Obviously, the endianness how to output the 16 result bits must be decided and declared by an implementation. (Probably little-endian byte order should be preferred, because most CPU hardware available today uses the this byte order.)

The output octets of Pike can be used as a pseudorandom stream.

For encryption and decryption, this output stream is usually XOR-combined with the input stream in order to create the (encrypted or decrypted) output data.

PIKE must re-seeded after generating 2^32^ output words (8 tebibytes). The method of re-reeding is not defined by PIKE's specification. One possibility would be to use another "seeding" instance of PIKE for initial seeding and later re-seeding of a second "working" instance.

The seed (its cryptographic key) of the generator is the initial state of the three 32-bit arrays `a[55]`, `b[57]` and `c[58]`, i.e. 5440 bit (680 octets in 170 words of 32 bit).

As usual for this kind of generators, at least one of the seed words in each array must be odd. I suggest setting the least significant bit of the first word in an array to 1 if all words in that seed array were initially even.

Also the seed values should already look "random", because if an array were filled with only small values, the associated generator needed a lot of time to "warm up" and start producing random-looking values.

Experimentation has shown that about 2000 cycles of the generator are sufficient to recover even from the worst seed, that is all seed array entries being zero (before setting the least significant bit of the first array element to 1 as suggested above).

Adding about 50 % to that number just to be sure, I recommend to throw away the results of the first 3072 cycles (following the initial 8 cycles which produce no output at all) before starting to produce actual output. Then one does not need to concern oneself with the bit pattern distribution of the seed. Of course, sufficient entropy is still required for a secure key.

This throwing away of the initial output can be skipped if the seed has been produced by another high-quality cryptographically secure pseudo random number generator (CSPRNG) or by a cryptographic key derivation function (KDF).

Variations for implementing Pike:

* Choice of the byte order for input (the 32-bit seed words)
* Choice of the byte order for output (the 16-bit result words)
* Using the bit parity instead of the carry bits for the control decisions
* Define an external algorithm (such as PBKDF2) for deriving the seed words from a pass phrase with low-density entropy (such as a human-provided pass phrase)

A problem with PIKE is that the description in its original paper leaves some room for interpretation. The above description is the best I could make of that description.

The paper proposing the algorithm is Ross Anderson's "On Fibonacci keystream generators," published in the FSE 1994 proceedings, LNCS 1008, pages 346–352.
